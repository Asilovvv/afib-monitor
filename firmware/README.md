# AFib Monitor: прошивка для M5Stack CoreS3 SE + AD8232

Что в папке:

| Файл | Что это |
|---|---|
| `AFibMonitor/AFibMonitor.ino` | Открыть в Arduino IDE |
| `AFibMonitor/afib_main.cpp` | Код прошивки: АЦП, фильтр, детектор R-зубцов, модель, экран |
| `AFibMonitor/afib_model_data.h` | Обученная модель int8 (RR-TCN, 27 КБ) — уже вставлена |
| `models/` | Модель на сырой ЭКГ (для сравнения в дипломе) и `.tflite` |
| `afib_stream.py` | Скрипт: шлёт настоящие ЭКГ из MIT-BIH на устройство, считает точность на чипе |

## 1. Подключение (3 провода «папа-мама»)

Разъём M5-Bus снизу CoreS3 SE (30 контактов):

| AD8232 | CoreS3 SE (M5-Bus) |
|---|---|
| GND | контакт 1 — GND |
| OUTPUT | контакт 2 — **G10** (АЦП) |
| 3.3V | контакт 12 — 3V3 |
| LO+, LO−, SDN | не подключать |

Электроды: **красный** — правая рука (RA), **жёлтый** — левая рука (LA), **зелёный** — правая нога / низ живота (RL).
Во время замера не двигаться, ноутбук лучше от зарядки отключить (меньше помех 50 Гц).

## 2. Arduino IDE 2 (один раз)

1. Settings → Additional boards manager URLs:
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
2. Boards Manager → **esp32** by Espressif → Install (версия 3.x).
3. Library Manager → **M5Unified** → Install (M5GFX поставится сам).
4. Tools → Board → esp32 → **M5CoreS3**. Tools → USB CDC On Boot → **Enabled**.

TensorFlow Lite Micro отдельно ставить не нужно: он уже есть в esp32 3.x (проверено: GitHub Actions → Firmware собирает прошивку именно так).

План проверки на столе в день прихода платы — [BENCH_TEST.md](BENCH_TEST.md).

## 3. Модель (уже вставлена)

Обучена на Kaggle на MIT-BIH AF Database, проверка на 5 пациентах, которых модель не видела:

| Модель | Чувствительность | Специфичность | F1 | Размер int8 |
|---|---|---|---|---|
| A: TCN на сырой ЭКГ (10 с) | 63.9 % | 76.6 % | 0.65 | 34 КБ |
| **B: TCN на RR-интервалах (32 удара)** | **96.6 %** | **94.6 %** | **0.95** | **27 КБ** |

Прошивка сама определяет тип модели по форме входа. Детектор R-зубцов в прошивке — тот же алгоритм, что в ноутбуке (проверено: совпадение 1:1).
Первое решение появляется примерно через 30 секунд (нужно 32 удара), потом обновляется каждые 4 удара.

## 4. Загрузка

Подключи CoreS3 SE кабелем USB-C → выбери порт (`/dev/cu.usbmodem…`) → **Upload**.
Если порт не виден: зажми кнопку сбоку (RST) ~3 с до зелёного светодиода → режим загрузки → Upload.

## 5. Что на экране

* сверху — ЭКГ в реальном времени;
* полоса — сколько ударов собрано из 32;
* плашка: **NORMAL RHYTHM** (зелёная) / **AFIB DETECTED** (красная) / **CHECK ELECTRODES** (жёлтая);
* внизу: пульс (BPM), вероятность AFib, время работы модели (мс).

Новое решение — каждые 4 удара сердца по последним 32 ударам.

## 6. Демонстрация и замеры с компьютера

```bash
pip install wfdb pyserial numpy
ls /dev/cu.usbmodem*                     # узнать порт

# демо: запись пациента с AFib в реальном времени (на экране как живой пациент)
python afib_stream.py --port /dev/cu.usbmodem101 --record 08215 --rhythm AFIB
# то же для нормального ритма
python afib_stream.py --port /dev/cu.usbmodem101 --record 05261 --rhythm N

# точность прямо на чипе (для диплома): sensitivity / specificity / F1
python afib_stream.py --port /dev/cu.usbmodem101 --eval --minutes 20 --speed 10

# время инференса и RAM
python afib_stream.py --port /dev/cu.usbmodem101 --bench
```

Пока идёт поток с компьютера, устройство берёт сигнал из USB (сверху «SRC: USB»);
через 1,5 с после остановки возвращается к датчику AD8232.

## 7. Bluetooth (для мобильного приложения)

Устройство называется **AFib-Monitor** и само начинает рекламу по BLE после включения.
Сервис `8f1e0001-4b6a-4c5e-9a0b-3a1f2e7d0001`, MTU 185. Все числа little-endian.

**Статус** `8f1e0002-…` (read + notify), 13 байт:

| Байты | Поле |
|---|---|
| 0 | версия = 1 |
| 1 | состояние: 0 сбор данных, 1 норма, 2 ФП, 3 проверьте электроды |
| 2–3 | вероятность ФП × 1000 |
| 4–5 | пульс × 10 |
| 6–9 | время работы устройства, мс |
| 10–11 | время работы модели, мкс |
| 12 | заряд батареи, % (255 = неизвестно) |

Пакет отправляется при каждом новом решении (каждые 4 удара) и раз в 0,5 с, пока идёт сбор данных или нет сигнала.

**Живая ЭКГ** `8f1e0003-…` (notify), 46 байт, 125 Гц (каждый второй отсчёт после фильтра):

| Байты | Поле |
|---|---|
| 0–1 | номер пакета (для подсчёта потерь) |
| 2–5 | масштаб, float32: мВ = значение × масштаб |
| 6–45 | 20 отсчётов int16 |

Масштаб считается для каждого пакета, поэтому большие R-зубцы не переполняют int16.
