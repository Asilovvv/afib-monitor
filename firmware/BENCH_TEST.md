# День, когда пришла плата: проверка на столе

Прошивка уже собирается автоматически на GitHub при каждом изменении (Actions → **Firmware**): esp32 core 3.x +
M5Unified + TensorFlow Lite Micro компилируются без ошибок, готовый `.bin` лежит в артефакте `afib-monitor-firmware`.
Значит, в этот день не нужно чинить сборку — только прошить и записать цифры в диплом (места `[TO MEASURE]`).

## 0. Безопасность (всегда)
Пока электроды на теле, ни одно устройство в цепи не подключено к розетке: MacBook работает от батареи, CoreS3 SE
питается от ноутбука или пауэрбанка. У CoreS3 SE нет своей батареи. Модуль AD8232 не изолирован от сети.

## 1. Прошить (10 минут)
1. Одной командой в Терминале на Mac:
   `curl -fsSL https://raw.githubusercontent.com/Asilovvv/afib-monitor/main/tools/flash_m5.sh | bash`.
   Скрипт ставит инструменты в `~/afib-flash`, скачивает последнюю прошивку из GitHub (раздел Releases →
   firmware-latest), проверяет SHA-256 и прошивает. Запасной путь — Arduino IDE по разделу 2 README.
2. Upload. На экране: ЭКГ, полоса «собрано N из 32», плашка ритма.
3. ✅ Готово, если без датчика видна плашка **CHECK ELECTRODES**, а не перезагрузка.

## 2. Тот же результат, что в ноутбуке (30 минут)
```bash
python afib_stream.py --port /dev/cu.usbmodem101 --eval --minutes 20 --speed 10
python afib_stream.py --port /dev/cu.usbmodem101 --bench
```
* `--eval` шлёт записи MIT-BIH на чип и считает чувствительность/специфичность **на самом чипе**.
* ✅ Готово, если разница с int8-моделью в ноутбуке ≤ 1 п.п. (те же записи, тот же порог 0,5).
* `--bench`: время одного решения (мс) и свободная RAM → таблица 5.7 диплома.

## 3. Энергопотребление с INA219 (1 час)
* INA219 включается **в разрыв +5 В** питания платы (VIN+ — от источника, VIN− — к плате, общий GND),
  например через USB-переходник с выведенными контактами питания. Читать INA219 удобнее вторым устройством
  или ноутбуком через USB-I²C адаптер, чтобы измеритель не питался от измеряемой линии.
* Замерить 3 режима по 5 минут, записать средний ток и пиковый:
  1. экран включён, BLE подключён, модель работает (обычный режим);
  2. экран выключен, BLE подключён;
  3. модель отключена (только АЦП и BLE) — чтобы увидеть, сколько стоит сама нейросеть.
* Автономность = ёмкость аккумулятора (мА·ч) / средний ток (мА). Записать честно, с указанием режима.
* ⚠️ Схему подключения INA219 стоит один раз проверить по фото/схеме платы, прежде чем включать.

## 4. Живая ЭКГ с AD8232 (30 минут)
1. Электроды по разделу 1 README, сидеть спокойно 5 минут.
2. Сравнить пульс на экране с пульсом по часам / тонометру (± 5 уд/мин).
3. Сохранить 10-секундную ЭКГ из приложения или записью `--live 10` — это рисунок для диплома «сигнал нашего датчика».
4. Подвигать рукой 30 секунд — посмотреть, появляется ли ложная «AFIB» (ожидаемо: да, см. ml/NOISE_SQI.md).

## 5. Проверка «30 секунд» на чипе (15 минут)
1. Нажать на полосу статуса внизу экрана (или отправить `C` в Serial) — 30 с отсчёт, затем вердикт:
   REGULAR RHYTHM / IRREGULAR RHYTHM / REPEAT THE CHECK.
2. В Serial строка `CHECK verdict=… beats=… sqi=… irr=… bsqi=… calc_us=… free_heap=…` — записать `calc_us`
   (время расчёта на чипе) и `free_heap` в таблицу 5.7.
3. Через USB-стрим (`afib_stream.py`, запись MIT-BIH с ФП и без) сравнить вердикт с тем, что даёт сервер на тех же
   30 с. Код тот же (`check30.h`), на ПК он совпадает с сервером 40 из 40 (GitHub Actions → Firmware → parity).
4. ⚠️ Если `free_heap` после проверки < 50 КБ — включить PSRAM в настройках платы (Tools → PSRAM).
5. Сразу после `CHECK` идёт строка `PVC research beats=… pvc=… calc_us=… free_heap=…` — оценка ранних желудочковых
   сокращений (только для исследования, на экран не выводится). Записать `calc_us` и `free_heap` в таблицу 5.10.
   Через стрим записи 200 или 233 (много PVC) число `pvc` должно быть близко к серверному (на ПК — совпадение бит в бит,
   910 из 910 ударов, CI → Firmware → parity).

## 6. Многоразовые электроды: шум против гелевых (30 минут)
Требование из ноутбука 16 (`ml/SNR_REQUIREMENT.md`): шум от движения электродов не выше чем на 9 дБ ниже ЭКГ, шум мышц — на 18 дБ.
1. Один человек сидит спокойно. Записать по 30 с: гелевые электроды, затем многоразовые (3 раза каждые):
   `cd ~/afib-flash && venv/bin/python afib_stream.py --port /dev/cu.usbmodem101 --live 30 --out gel_1.csv`.
   Прошивка по команде `E 1` шлёт сырой АЦП 250 Гц. Если устройство потеряло отсчёты, скрипт предупредит.
2. `venv/bin/python afib_stream.py --snr gel_1.csv gel_2.csv gel_3.csv` — SNR определён так же, как в ноутбуке 16:
   мощность сигнала, отфильтрованного 0,5–40 Гц, к мощности шума за всю запись. Шум — то, что остаётся от каждого
   комплекса после вычитания усреднённого (с выравниванием точнее отсчёта). На синтетике с известным SNR 24/18/12/9/6 дБ
   оценка дала 23,9/18,5/12,7/9,9/5,2 дБ. На живой ЭКГ оценка будет немного ниже настоящей (занижена, то есть
   с запасом), потому что естественные отличия комплексов (дыхание) тоже считаются «шумом».
3. Если у многоразовых SNR < 18 дБ — режим «контроль» на них не включать.
