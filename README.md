# AFib Monitor — система обнаружения фибрилляции предсердий

Дипломный проект: **Ultra-Low-Power Atrial Fibrillation Detection via Quantized TCN on Microcontrollers**
Автор: Бектур Асилов, COMSE-23, Ala-Too International University.

```
[CoreS3 SE + AD8232] --BLE--> [Мобильное приложение] --HTTPS--> [Бэкенд + БД] --SSE--> [Веб-кабинет врача]
 int8 TCN на ESP32-S3          ритм, живая ЭКГ, SOS,             эпизоды, тревоги,        тревоги онлайн, ЭКГ,
 статус + ЭКГ 125 Гц           дневник, запись ЭКГ               ЭКГ, симптомы            разметка, отчёт
```

Нейросеть работает **на самом устройстве**. Телефон и сервер ничего не вычисляют, они только показывают, хранят и обобщают результаты.

| Папка | Что внутри | Технологии |
|---|---|---|
| `firmware/` | Прошивка, модель, скрипт демонстрации, ноутбук Kaggle | Arduino / ESP32-S3, TFLite Micro, BLE |
| `backend/` | REST API, база данных, аналитика эпизодов, тесты | Python, FastAPI, SQLAlchemy, SQLite / PostgreSQL, JWT |
| `web/` | Сайт проекта (лендинг) и кабинет врача | React 19, TypeScript, Vite, Recharts, SSE |
| `mobile/` | Приложение пациента (Android и iPhone) | React Native (Expo SDK 57), BLE, SVG, уведомления |
| `docs/screenshots/` | Скриншоты для диплома и презентации | |

Демо-аккаунты (создаются автоматически при `SEED_DEMO=1`):
- врач `doctor@demo.kg` / `demo1234`, код для пациентов `DEMO42`;
- пациенты `aibek@demo.kg`, `gulmira@demo.kg`, `nurlan@demo.kg`, `sabina@demo.kg`, `ermek@demo.kg` / `demo1234`.

При `SEED_DEMO=1` также включается **живое демо** (`backend/app/demo_live.py`): демо-пациенты каждые 6 секунд «присылают» показания,
поэтому в кабинете они онлайн, а время от времени начинается приступ ФП с настоящей тревогой и записью ЭКГ. Отключить: `DEMO_LIVE=0`.

## Что умеет версия 2 (Pro)

**Сайт и кабинет врача** (http://localhost:8000):
- лендинг проекта с живым ЭКГ-монитором, результатами модели и описанием системы;
- обзор: KPI, пациенты, требующие внимания, нагрузка ФП, лента тревог;
- тревоги в реальном времени (SSE): всплывающее уведомление и звук, отметка «принято»;
- пациенты: поиск (клавиша `/`), фильтры, сортировка, мини-графики пульса;
- карточка пациента: пульс и эпизоды за 24 ч / 7 / 30 дней, минуты ФП по часам, эпизоды с разметкой «ФП подтверждена / ложная тревога», ЭКГ на миллиметровке (25 мм/с, RR-интервалы), симптомы, заметки врача;
- печатный отчёт (PDF через печать), настройки профиля, код для пациентов, светлая/тёмная тема, RU/EN.

**Приложение пациента**:
- онбординг, вход/регистрация с проверкой сервера, режим без сервера;
- монитор: анимированное сердце в такт пульсу, кольцо вероятности ФП, **живая ЭКГ** по Bluetooth;
- при начале ФП: вибрация, уведомление и **автоматическая запись ЭКГ** (10 с), которая уходит врачу;
- запись ЭКГ вручную, дневник симптомов с выраженностью и ЭКГ, кнопка **SOS (103)** и звонок врачу;
- история: нагрузка ФП, эпизоды с решением врача, графики, просмотр записанных ЭКГ;
- экран устройства: батарея, сигнал Bluetooth, время инференса на чипе, потери пакетов, синхронизация;
- светлая/тёмная тема, русский/английский, офлайн-очередь (данные не теряются без интернета).

## 1. Запуск на компьютере (Mac)

**Бэкенд и веб-кабинет**, в первом терминале:
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
SEED_DEMO=1 uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Во втором терминале, один раз, собрать веб-кабинет:
```bash
cd web && npm install && npm run build
```
Затем открыть http://localhost:8000 — это кабинет врача. Документация API: http://localhost:8000/docs.
Для разработки веба с автообновлением: `cd web && npm run dev` → http://localhost:5173.

Тесты бэкенда: `cd backend && pytest -q`.

## 2. Мобильное приложение

Для Bluetooth нужна **development build**, в Expo Go Bluetooth не работает:
```bash
cd mobile
npm install
npx expo run:android      # телефон Android по USB (нужен Android Studio)
# или
npx expo run:ios          # iPhone (нужен Xcode)
# или сборка в облаке без Android Studio:
npx eas-cli@latest build --profile development --platform android
```

В приложении:
1. При первом входе: адрес сервера (в одной Wi-Fi сети: `http://<IP-Mac>:8000`, после деплоя: `https://….onrender.com`), вход или регистрация. Кнопка «Демо-пациент» подставляет `aibek@demo.kg`. Код врача (`DEMO42`) привязывает пациента к врачу.
2. **Монитор → «Подключить устройство»**: телефон найдёт плату *AFib-Monitor* по Bluetooth.
   **«Демо-режим»** показывает всё без платы: симулятор шлёт те же пакеты, что и прошивка (статус + ЭКГ 125 Гц, норма ↔ ФП).
3. Данные отправляются на сервер каждые 20 секунд. Без интернета они копятся в очереди на телефоне.
4. При начале эпизода ФП приходит уведомление и вибрация, ЭКГ приступа сама уходит врачу.

Быстрый просмотр интерфейса в браузере (без Bluetooth): `cd mobile && npx expo start --web`.

## 3. Размещение в интернете (бесплатно, Render.com)

1. Загрузить папку на GitHub (без `node_modules`, всё лишнее исключено в `.gitignore`).
2. render.com → **New → Blueprint** → выбрать репозиторий. Файл `render.yaml` сам соберёт `Dockerfile` (веб + API в одном контейнере).
3. Через 5–10 минут появится адрес вида `https://afib-monitor.onrender.com`. Его нужно ввести в приложении.

По умолчанию данные хранятся в SQLite. На бесплатном тарифе Render они сбрасываются при перезапуске, для демо это нормально, демо-данные создаются заново.
Для постоянного хранения подключите PostgreSQL через переменную `DATABASE_URL`.

## 4. API (кратко)

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| POST | `/api/auth/register` | все | регистрация (`role`: patient/doctor, `doctor_code`) |
| POST | `/api/auth/login` | все | вход, выдаёт JWT |
| GET | `/api/me` | все | профиль |
| PUT | `/api/me/doctor` | пациент | привязать врача по коду |
| POST | `/api/readings` | пациент | пакет показаний `{ts, state, prob, bpm}` |
| GET | `/api/me/report?hours=24` | пациент | статистика и эпизоды |
| GET | `/api/patients` | врач | пациенты, тревоги, нагрузка ФП за 24 ч |
| PUT | `/api/me` | все | изменить профиль |
| POST | `/api/symptoms` | пациент | симптом `{kinds[], severity 1–3, note}` |
| POST | `/api/ecg` | пациент | запись ЭКГ `{ts, fs, samples[], reason}` |
| GET | `/api/ecg/{id}` | пациент / его врач | отсчёты ЭКГ |
| GET | `/api/overview` | врач | KPI и последние тревоги |
| GET | `/api/alerts?status=new` | врач | тревоги; `POST /api/alerts/{id}/ack`, `/api/alerts/ack-all` |
| GET | `/api/patients/{id}/report?hours=24` | врач | пульс, эпизоды, по часам, симптомы, ЭКГ, заметки |
| POST | `/api/patients/{id}/notes` | врач | заметка (удаление: `DELETE …/notes/{id}`) |
| POST | `/api/patients/{id}/episodes/review` | врач | разметка эпизода: `confirmed` / `false_alarm` / `clear` |
| GET | `/api/stream?token=…` | врач | поток событий SSE: `alert`, `reading`, `symptom`, `ecg` |

**Как считается аналитика** (`backend/app/analytics.py`):
- **эпизод ФП** — подряд идущие показания «ФП» без разрывов больше 60 с и общей длительностью не меньше 30 с (клиническое правило);
- **нагрузка ФП (AF burden)** — доля времени мониторинга, проведённая в ФП;
- **тревога** у врача создаётся в момент перехода «норма → ФП» и сразу приходит в кабинет по SSE.

## 5. Что проверено

- Бэкенд: автотесты (регистрация, роли и доступ, загрузка, эпизоды, правило 30 с, тревоги, симптомы, ЭКГ, заметки, разметка, доступ к потоку SSE).
- Веб: сборка без ошибок, все страницы проверены в браузере (светлая и тёмная тема, телефон), тревога в реальном времени — `docs/screenshots/`.
- Мобильное приложение: TypeScript без ошибок, Android-бандл собирается, весь сценарий (онбординг → вход → демо-режим → ФП → запись ЭКГ → симптом → история → профиль) проверен в веб-превью с реальным сервером.
- Протокол BLE: разбор пакетов статуса и ЭКГ в приложении совпадает с форматом прошивки.
- Прошивка с BLE компилируется для M5Stack CoreS3. **На реальной плате ещё не запускалась**, это первый шаг после прихода деталей.
