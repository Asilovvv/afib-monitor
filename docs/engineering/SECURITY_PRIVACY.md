### 1.3 Findings of the 29.10.2026 review

| ID | Severity | Finding | Status / plan |
|---|---|---|---|
| F-01 | medium | The per-address login limit (50 wrong passwords in 15 min) uses the address uvicorn sees. On Render that is the proxy, because uvicorn is not told to trust forwarded headers, so 50 wrong passwords from anywhere can make every login wait up to 15 minutes. | **Open.** Fix after checking which header Render sets for the client address (a community report says the proxy appends to `X-Forwarded-For`; not confirmed by Render's documentation). Until then the per-account limit is the real protection. |
| F-02 | medium | Live-stream token and one-time export token written to the server log as part of the URL. | **Fixed** 29.10.2026 (4ea1d72), with a test. Tokens already in old Render logs stay valid until they expire (30 days); rotating `JWT_SECRET` ends them. |
| F-03 | low | The portal keeps the JWT in `localStorage`, readable by any script that runs on the page. | Open, mitigated: no user-supplied HTML is rendered; a Content-Security-Policy (F-07) would reduce it further. |
| F-04 | medium | Tokens live 30 days and cannot be revoked server-side; "log out" deletes only the local copy. Deleting the account does end them. | Open. Plan: a token version per user (incremented on log-out-everywhere and password change). |
| F-05 | low | The stream token travels in the URL (browser EventSource cannot send headers). | Accepted (`SECURITY.md` #5); our log now masks it (F-02); a short-lived stream token is the clean fix. |
| F-06 | medium | No password change and no password reset. | Open. A reset needs e-mail delivery (not configured). |
| F-07 | low | No Content-Security-Policy. | Open: needs testing of inline styles and fonts before it can be switched on. |
| F-08 | low | The app keeps the JWT in AsyncStorage, not the Keychain / Keystore. | Open. Plan: `expo-secure-store`. |
| F-09 | low | The Telegram webhook secret was compared with `!=` instead of a constant-time comparison. | **Fixed** 29.10.2026 (`secrets.compare_digest`); `test_telegram_flow` still passes. |
| F-10 | medium | BLE without pairing or encryption: anyone in radio range can read the rhythm state and ECG while the sensor is on (packets carry no name). | Open. Needs LE Secure Connections bonding in the firmware and the app, then a bench test. |
| F-11 | low | The app accepts any server address, including `http://` (needed for local development), so a user could send data unencrypted. | Open. Plan: refuse `http://` for non-local addresses in release builds. |
| F-12 | info | CORS `*`. | Accepted: bearer tokens, no cookies. |
| F-13 | low | No rate limits on registration, uploads or feedback (size caps exist). | Open. |
| F-14 | low | 9 advisories (4 high, 5 low) in the app's Expo build tools (`@expo/cli`, `@expo/config`, `node-forge`, `zod`, `deepmerge`). | Accepted for now: the production source map shows none of these packages in the app bundle (only Metro's module loader from `@expo/cli`); a patch update (`expo` 57.0.27 → 57.0.31) is available and is postponed until after the phone tests of board day part B so the iPhone build does not change before them. |
| F-15 | — | No automatic retention limit (see §2.3). | Open, privacy. |
| F-16 | low | The public server runs with demo accounts whose passwords are published (`SEED_DEMO=1`). | Accepted for the demonstration; guarded by the `@demo.kg` rule; set `SEED_DEMO=0` for real patients. |

**Not reviewed:** an independent penetration test, the firmware against physical attacks, the hardware's electrical safety
(IEC 60601-1 — needs an electronics engineer).

### 2.2 Legal basis — what is still open

Consent is recorded per kind and text version, and research consent can be withdrawn (the patient then falls back to
wellness mode at once). Whether this meets the Kyrgyz law on personal information for **health data**, whether a
**cross-border transfer** to the USA (Render, Oregon; Neon) is allowed, and whether the data holder must be registered are
questions for a lawyer, listed in `docs/REGULATORY_BRIEF_RU.md`. **A lawyer must answer them before data of real patients
(not demo accounts, not the author) is stored on the public server.** The privacy policy already says data will move to a
server in Kyrgyzstan or the EAEU for real use.

### 2.3 Storage, retention, deletion, anonymization

* **In transit:** HTTPS. **At rest:** whatever the providers apply; not configured or verified by us.
* **Retention:** records are kept until the user deletes the account; there is **no automatic retention limit** yet (F-15).
  Short-lived items expire: export links 10 min, Telegram link codes 24 h, family invites 7 days. The pilot protocol sets its
  own periods (`docs/pilot/PROTOCOL_RU.md`: identity sheet on paper, destroyed 12 months after the study; de-identified data
  5 years — both pending the ethics committee).
* **Deletion:** `DELETE /api/me` (password required) removes every row about the user in reference order on SQLite and
  PostgreSQL; tested, including the case that once failed on PostgreSQL (0801d2e).
* **Portability:** full JSON export, import into an empty account.
* **Anonymization:** for the pilot, `tools/pilot_blind.py` builds a reading pack with random codes and no names, dates or
  algorithm verdicts; the key stays with the engineer. The owner's status page shows counts only.

## 3. Ethics

* **Bias.** The model was trained on MIT-BIH AFDB (23 people, Holter recordings from the 1980s, one US database) and
  tested on CinC 2017 (single-lead hand-held recordings) and LTAFDB. There are no recordings from Central Asia and none from
  children; performance by age and sex has not been measured. The only body data so far is from the author. The thesis must
  state this as a limitation.
* **False reassurance and false alarms.** The live screen gives no verdict; a person's result comes from the 30-s check;
  "see a doctor" only after two irregular checks in a row. A regular result says "your rhythm was regular for 30 seconds;
  if you feel unwell, see a doctor anyway", not "no AF"; an irregular one says "this is not a diagnosis" and names movement
  and loose electrodes as causes (app and printed guide); SOS 103 is on the main screen. Measured false "irregular" at rest:
  0.4–2.4 % of 30-s windows in healthy adults, about 10 % below 60 beats/min (`ml/ROUND4_REST.md`).
* **Harmful automation.** AF alerts go only to pilot participants with research consent and a doctor; Telegram alerts wait
  30 s of sustained AF (0.91 false alarms per hour of normal rhythm instead of 4.6, at 205 of 226 episodes —
  `ml/LOPO_RESULTS.md`).
* **Surveillance.** Relatives see a minimum in plain words and the patient can revoke them; every doctor access is visible to
  the patient.
* **Misuse.** The device is marked "not a medical device" everywhere; demo accounts cannot be linked to real patients.
* **Human participants.** Board-day measurements were done by the author on himself; his raw recordings are not in the public
  repository. The usability study and expert review (`EVALUATION_PLAN.md`) need the department's approval and written
  consent before the first session; the clinical pilot needs an ethics committee (`docs/pilot/`).

## 4. Accessibility

**Doctor portal and public pages** — measured with `tools/a11y_audit.mjs` (axe-core 4.14.0, WCAG 2.1 A/AA rules,
13 pages × light and dark theme, plus a keyboard pass): see `TEST_REPORT.md` §6. First run: 0 critical, **18 page/theme
combinations with serious contrast violations**, a search box without visible focus and an account menu (with "Log out")
that the keyboard could not reach, the brand name invisible on the legal pages in the light theme, `<html lang>` fixed to
Russian. After the fixes (92da4cb): **0 violations**, every Tab stop shows focus, no clickable element outside the Tab order.
Also in place: labels on form fields, alt text on images, `prefers-reduced-motion` respected, responsive layout down to
phone width.

**Patient app.** Large-text mode and voice prompts (Russian, Kyrgyz) in Profile; system font scaling is not disabled
anywhere; buttons with visible text are read from that text; 8 icon-only controls carry explicit labels.

**Known limitations.** No test with real screen readers (VoiceOver, TalkBack, NVDA); the app's contrast and labels were not
audited control by control; the ECG and Poincaré charts have no text alternative beyond the numbers shown next to them;
colour coding (red / amber / green) is always paired with words, but this was checked by reading the code, not with users.
