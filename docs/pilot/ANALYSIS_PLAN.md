# План анализа пилота (фиксируется до первого включения)

Версия 1.0 от 27 октября 2026 г. К протоколу `docs/pilot/PROTOCOL_RU.md` v0.1. Этот файл коммитится **до** включения
первого участника; любое изменение после — только новой версией с датой и причиной, старая остаётся в истории git.
Расчёт делает `tools/pilot_analyze.py`; он проверен на синтетических данных (`tools/pilot_selftest.py`) до начала набора.

## 1. Данные

- **Записи:** 30-секундные проверки (`reason = "check"`) каждого участника за дни 1–14 после визита 1. Источник — экспорт
  данных участника («Скачать мои данные», формат `afib-monitor-export/1`), сделанный на визите 2 с согласия участника.
  Записи вне дней 1–14 и пробные записи визита 1 в анализ не входят.
- **Вердикт алгоритма** пересчитывается из записи функцией `backend/app/ecgtools.check` той версии, которая зафиксирована
  на дату начала набора (тег git `pilot-start`); сохранённое на сервере значение не используется.
- **Чтение кардиолога:** по каждой записи одна из меток: `sinus` (синусовый ритм), `af` (ФП или трепетание предсердий),
  `other_irregular` (другой нерегулярный ритм), `unreadable` (не читается). Кардиолог видит только запись и случайный код,
  без вердикта алгоритма, без имени и без даты (`tools/pilot_blind.py`). Ключ «код → участник, время, вердикт» хранится
  у инженера и передаётся только после того, как все метки введены.
- **План проверок** — из экспорта (`check_plan.times`), часовой пояс UTC+6.

## 2. Конечные точки и пороги успеха (заранее)

| # | Что | Как считаем | Успех |
|---|---|---|---|
| E1 (основная) | Записи с вердиктом | для каждого участника: доля записей, где вердикт ≠ `no_verdict`; **медиана по участникам** | медиана ≥ 0,80 |
| E2 (основная) | Выполнение расписания | для каждого участника: `done / due` по правилу сервера (`analytics.check_adherence`: каждая проверка засчитывается одному плановому времени в пределах ±90 мин); **медиана по участникам** | медиана ≥ 0,70 |
| E3 | Согласие с кардиологом | только записи, где алгоритм дал вердикт **и** кардиолог не поставил `unreadable`. Сопоставление: `sinus` → «ровный», `af` и `other_irregular` → «неровный». Доля совпадений и каппа Коэна | порога нет (описательно); при < 30 пар — только доля совпадений |
| E3a | Чувствительность к ФП / доля «неровный» при синусе | среди записей с меткой `af`: доля «неровный»; среди `sinus`: доля «неровный» | описательно |
| E4 | Качество сигнала | SNR каждой записи (определение `ml/SNR_REQUIREMENT.md`, частота 125 Гц, `mobile/src/snr.ts` = Python ±1 дБ); доля записей с SNR ≥ 18 дБ, медиана по участникам | описательно; < 18 дБ у большинства — сигнал к доработке электродов |
| E5 | Удобство | SUS: (сумма (ответ−1) по нечётным + (5−ответ) по чётным) × 2,5; медиана и квартили | описательно; ≥ 68 — «выше среднего» по шкале SUS |
| E6 | Нежелательные явления | число участников с ≥ 1 явлением, по типам (`AE_LOG`) | любое серьёзное — остановка по протоколу §11 |
| E7 | Технические отказы | доля проверок, отклонённых из-за пропусков Bluetooth (`gaps`), разрывы связи по журналу поддержки | описательно |

## 3. Доверительные интервалы

- Доли по участникам (E1, E2, E4): медиана и **кластерный бутстрэп** по участникам (2 000 повторов, seed 0), 95 % перцентильный интервал.
- Объединённые доли (для сравнения с открытыми данными): интервал Уилсона, с пометкой, что записи одного человека зависимы.
- Каппа (E3): кластерный бутстрэп по участникам, 2 000 повторов, seed 0.

## 4. Что считается отклонением и как сообщается

- Участник выбыл до дня 7 — его данные входят в E1, E4–E7, но не в E2 (знаменатель неполный); сообщаем число выбывших и причины.
- Изменение версии приложения во время пилота (только критические исправления) — запись в журнале отклонений с датой.
- Если кардиолог поставил `unreadable` больше чем 30 % записей — сообщаем отдельно, E3 считаем как есть.
- Никаких подгрупп и порогов, не названных здесь. Любой дополнительный анализ помечается «апостериорный».

## 5. Что этот пилот не может показать

Точность алгоритма в смысле регистрации изделия (выборка 10–20 человек мала, у всех уже есть ФП), пользу для здоровья,
поведение на людях без диагноза ФП. Это повторяется в отчёте рядом с результатами.
